# 内网论文自动评审工具需求文档

版本：V0.1　状态：待方案确认　日期：2026-11-08  
对应项目：`thesis_review_agent`　适用读者：业务负责人、评审专家、研发与内网运维负责人

## 1 文档目的与确认结论

本项目拟建设一个在内部环境运行的论文评审辅助工具。用户上传论文和参考规范，可补充评审重点；系统在本地完成解析、模型评审、证据校验与报告生成，输出可以回到原文核查的问题和修改建议，帮助评审人员发现值得优先处理的问题。

**建议确认的建设方向：保留现有网页、FastAPI、LangGraph 和本地文件存储，先完成内网真实模型的文本评审试点，再补齐图像解析、长文审查和查证能力。** 现有 demo 已完成工作流验证，尚不能作为真实论文质量评估能力或正式内网安全部署的验收结果。

本文确认“需要完成什么、以什么标准验收”；配套《技术方案》说明模块、接口、数据与实施方法。文末 D01—D08 是需要上游决定的事项；本版不代表这些事项已经获批，也不承诺尚未测量的准确率和响应时间。

## 2 已确认条件

| 项目 | 已知条件与约束 |
| --- | --- |
| 使用目的 | 对提供的论文及学位阶段材料进行有证据、可核查的辅助评审 |
| 材料类型 | 开题报告、中期报告、毕业／学位论文、中文或英文小论文 |
| 输入形式 | PDF、DOCX、图片、粘贴文本；可选提示词；提供 PDF 等格式的考核要求文件 |
| 隐私要求 | 论文内容不得外传；模型、解析、存储应在本地或内部环境运行 |
| 模型要求 | 接入内部部署、参数量大于 8B 的模型；“Codex”指具有工具调用能力的本地 agent 方向，不要求使用 Codex CLI |
| 硬件与规模 | 现有一张 A100，预计并发不大；显存容量、主机配置、材料规模待确认 |
| 当前开发条件 | 开发者暂不在内网，先通过模拟器、接口契约与本地文件完成开发；暂不依赖后端数据库 |
| 工程原则 | 代码简洁、职责清晰、模块解耦；避免无必要的检查、回退、层次和中间产物 |
| 代码目录 | `thesis_review_agent` 是代码根目录，不要求重命名外层工作目录 |
| 联网边界 | 严格隔离和受控联网两种模式均需保留比较，尚未最终选定 |

## 3 使用角色与业务流程

### 3.1 角色

| 角色 | 预期职责 | 当前支持情况 |
| --- | --- | --- |
| 材料提交者／评审人员 | 提交材料、指定阶段与重点、查看报告和证据、核查建议 | demo 为本机单用户操作，未建立账号角色 |
| 规范维护人员 | 提供并确认规范来源、版本、有效期、适用对象 | demo 仅支持上传和选用参考文件 |
| 领域专家 | 核查关键意见、评价误报漏报、决定最终学术结论 | 由系统外人工完成 |
| 系统／安全管理员 | 部署模型、配置访问与出网边界、管理备份和保留策略 | 正式部署职责待落实 |

### 3.2 主流程

1. 上传或粘贴材料，选择开题／中期／学位论文／小论文、学位层次和语言。
2. 选择适用规范，填写可选评审重点，提交任务。
3. 系统提取文本及位置；明确提示无法解析的页、图片、公式或其他内容。
4. 内部模型按四个维度审查；需要外部证据时，按已确认的联网模式处理。
5. 对问题的引用、出处和必要的核查结果进行校验，输出总体判断、关键问题及优先事项。
6. 用户查看原文、下载格式化报告；重大结论由领域专家复核。

未取得具体规范时按一般学术质量要求审阅。未能完成的检查应标明范围和原因，不能以没有发现问题代替“已经完整核验”。

## 4 评审内容要求

### 4.1 四个评审维度

| 维度 | 应检查的内容 | 输出边界 |
| --- | --- | --- |
| 结果可信度 | 数据来源、实验设置、对比方法、评价指标；数据泄漏、不公平比较、选择性报告；图表与正文、样本数、均值、提升幅度的一致性；结论证据与异常矛盾 | 指出具体数据、日志或补充实验的核查需求；无原始材料不得认定数据造假 |
| AI 生成痕迹与内容可靠性 | 残留提示词、对话语句、占位内容、反复套话、风格突变、术语混乱、错误解释；疑似虚构的文献、公式、事实 | 引用具体片段并解释质量问题；区分一般写作问题与未经核实内容，不凭文风认定 AI 代写，不给 AI 生成比例 |
| 规范性与逻辑完整性 | 引用和成果归属；图表、公式、单位、术语、参考文献规范；题目、问题、方法、实验和结论之间的对应；概念错误、论证跳跃、夸大及章节拼接 | 优先处理影响理解或结论成立的问题，排版小错简列；不得编造制度条款 |
| 创新性与研究价值 | 学术或应用价值；相对最接近工作的新增贡献；创新证据；改名、调参、简单组合、应用迁移的实质贡献 | 未核实相关工作不能断言没有创新；不机械否定有实质贡献的组合创新，不把性能提升自动等同创新 |

### 4.2 材料阶段与学位层次

| 材料 | 判断重点 | 不应作出的要求或推断 |
| --- | --- | --- |
| 开题报告 | 问题价值、拟创新点、技术路线、验证方案和可行性 | 不要求已经存在最终实验结果 |
| 中期报告 | 实际进展、阶段结果、主要困难、剩余工作能否完成 | 不把计划写成已实现成果 |
| 毕业／学位论文 | 研究完整性、结果对贡献的支撑、章节统一主线、本人贡献 | 不以单项实验提升代替整体研究评价 |
| 小论文 | 核心贡献、方法正确性、实验充分性及投稿质量 | 不未经依据判定达到某会议或期刊录用标准 |

本科侧重完整规范与基本能力，硕士关注有价值的问题和相应研究贡献，博士更重视实质创新与独立研究深度；专业学位同时关注实践创新。层次不明时给出判断条件，不默认套用博士标准。

语言要求：开题、中期和学位材料用中文；中文小论文用中文，英文小论文默认英文；用户明确指定时服从指定。当前 demo 由用户手动选择语言，尚未实现材料语言自动识别；报告固定标题和枚举仍包含中文，完整英文呈现需补齐。

### 4.3 报告结构

1. **总体判断**：使用“基本满足／需修改／存在重大问题／信息不足”之一，并说明主要原因。
2. **关键问题**：按严重程度排序，采用下表字段；只列有依据的问题，疑点标注“待核实”，不凑数量。
3. **优先处理事项**：列出最应先修改或核查的内容，必要时提供少量替换文字。
4. **审查范围与限制**：说明材料覆盖、缺失证据、未完成的检查及模拟／真实执行情况。

| 维度 | 严重程度 | 具体位置与原文／数据依据 | 问题及影响 | 修改或核查建议 |
| --- | --- | --- | --- | --- |
| 按实际检查填写 | 按实际影响填写 | 可回溯到材料或已核验来源 | 说明依据与影响，疑点写明待核实 | 给出可执行的修改或核查方法 |

上表仅为字段说明，不是评审结果。不得编造页码、文献、实验或核验记录，不输出复杂评分体系、长篇制度解读或重复检查清单。系统意见用于辅助评审，不代替专家的最终结论。

## 5 功能需求与当前差距

“目标必需”指完整业务目标；是否进入首个内网试点以 D01 确认为准。demo 已实现表示存在可运行代码，不表示真实模型效果已验收。

| 编号 | 功能需求 | 当前 demo | 后续范围 |
| --- | --- | --- | --- |
| R01 | 接收 PDF、DOCX、图片和文本，支持多材料及明确来源 | 已有上传、文本输入、原件保存与下载 | 目标必需：图片／扫描件内容识别；上传成功不等于已理解内容 |
| R02 | 设置材料阶段、学位层次、语言和可选提示词 | 已有主要字段；无单独专业学位字段和语言自动选择 | 目标必需：补齐尺度字段、默认语言和完整报告本地化 |
| R03 | 提供并选用考核要求，适用性明确且可引用 | 所选规范全文作为模型参考 | 目标必需：确认文件来源、版本、适用范围；缺失时限定合规结论 |
| R04 | 完成四维评审并遵守证据边界 | 已有系统提示词和模型适配；模拟模式只检查标记 | 目标必需：真实模型联调与专家样本验证 |
| R05 | 问题可回溯；数据或结论不确定时提出具体核查需求 | 校验 block_id 和原文子串，返回材料位置 | 目标必需：补齐数值一致性、语义支持及外部来源复核；字面匹配不等于结论成立 |
| R06 | 输出固定结构报告，支持查看原文、下载和历史查询 | 已有 JSON／Markdown 报告及历史任务 | 目标必需：全文覆盖与语言完善；不以任务完成状态表示论文通过 |
| R07 | 接入内部部署、参数量大于 8B 的模型，失败不回退云端 | 已有 OpenAI-compatible 接口；未完成 A100 联调 | 目标必需：确定模型、精度、上下文及结构化输出能力 |
| R08 | 使用本地 agent 编排，工具权限与数据路径明确 | LangGraph 四节点已接入，调用固定模块 | 工具调用方向已确认；模型自主选择工具的循环是否首期实施由 D05 决定 |
| R09 | 支持公开信息查证并将真实证据用于审计意见 | 独立手动批准 Crossref 查询；未自动写入报告 | 目标必需：按 D02 选择资料导入或受控查询，建立来源与问题关联 |
| R10 | 创建、查询、取消任务，显示阶段和失败原因 | 已有单线程队列、阶段状态、取消、重启中断标记 | 试点继续串行；自动重试／续跑及多并发按需要另行确认 |
| R11 | 暂用固定本地目录保存材料、请求、状态、报告和检索记录 | 已实现，支持 DATA_ROOT 配置 | 试点可沿用；正式保留、删除、备份和权限策略需确认 |
| R12 | 明确部分审查、无法解析、检索不足和模型失败 | 已有文本提取警告、超限拒绝与错误状态 | 目标必需：长文分章与跨章一致性；按真实检查范围生成覆盖说明 |

## 6 隐私与非功能要求

### 6.1 联网模式选择

| 比较项 | 模式 A 严格隔离 | 模式 B 受控联网 |
| --- | --- | --- |
| 论文处理 | 在内部环境解析、推理、存储 | 同左 |
| 公共资料获取 | 在外部预先同步与当前论文无关的公开资料，经允许的导入流程进入内网 | 内网提出查证需求，批准精确查询后由独立网关发出 |
| 任务是否能实时上网 | 不能；只查询已导入资料 | 可以，但只能发送获批的公开查询 |
| 主要限制 | 新颖工作和冷门领域覆盖受资料库更新范围限制 | 公开词条组合也可能泄露研究方向，需审查与网络策略 |
| 对 R09 的影响 | 实现本地资料检索，实时联网需求需明确接受调整 | 可逐步实现受控自动查证与证据回流 |
| 当前状态 | 尚未部署正式隔离环境 | 当前手动 approved 标志不构成正式网关或身份授权 |

**D02 未确认前，内网试点建议默认关闭任务驱动的外部查询，保留本地资料查证。** 这是待批准的实施建议，不代表已经选择模式 A。无论采用哪种模式，都不允许论文原文、内部题目／项目、实验数值、图片和完整提示词发送给公网服务或云模型。

### 6.2 非功能要求

| 编号 | 要求 | 验证方式 |
| --- | --- | --- |
| N01 数据不外传 | 推理、OCR、向量化、日志、备份和前端资源按选定边界部署；禁止云端模型回退及论文上下文云追踪 | 内网部署时结合出站策略、访问日志和失败测试验证，不能只检查提示词 |
| N02 可维护性 | 保持模块职责明确；接口、字段和错误可定位；存储实现可替换 | 代码审查、接口契约和单任务目录排障 |
| N03 可靠性 | 取消后不发布迟到结果；重启后未完成任务明确标记；失败不得伪装为成功 | 自动化测试及内网故障演练 |
| N04 资源与性能 | 单 A100、低并发起步；正文长度、排队、耗时和显存使用可测量 | 用确认后的典型材料测量；暂不承诺每篇耗时和并发数 |
| N05 访问与生命周期 | 多用户使用前具备身份与材料访问控制；明确保留、删除和备份恢复责任 | 权限隔离、删除验证及恢复演练；本机 demo 不视为多用户服务 |

## 7 分阶段交付与验收

### 7.1 交付阶段

| 阶段 | 范围 | 进入下一阶段的条件 |
| --- | --- | --- |
| M0 本地 demo | 现有网页、LangGraph 四节点、模拟器、模型接口、本地存储、手动公开查询 | 当前已具备；已有 12 项自动化测试通过记录，验证工程流程，不验证学术效果 |
| M1 内网文本评审试点 | 部署真实模型；选用已确认规范；用可提取文本材料评审；保留串行与本地存储；落实试点访问和出网策略 | 内网模型契约通过，专家复核试点样本，运行与隐私检查通过；试点不能宣称完成图片／全文目标 |
| M2 完整输入与查证 | 本地 OCR／版面处理、长文与跨章审查、语言完善、证据复核；按 D02 接入资料检索或受控查证 | R01—R12 目标内能力按批准范围验收；未完成项明确登记，不隐藏降级 |
| M3 按需扩展 | 多实例、数据库、任务重试与检查点、向量库、SSE 等 | 根据实际并发、历史追溯和运维需求单独立项；不作为现有 demo 的前置条件 |

### 7.2 可执行验收用例

| 用例 | 对应需求 | 通过条件 |
| --- | --- | --- |
| A01 输入与来源 | R01、R05 | 正文和规范可关联到来源；PDF 用真实物理页、DOCX 用段落／表格行等有效位置，不生成虚假页码 |
| A02 无可读内容 | R01、R12 | 无 OCR 时图片不能被宣称已审；具备 OCR 后用扫描样本验证内容和位置，识别失败明确反馈 |
| A03 尺度与规范 | R02、R03、R04 | 同一材料按阶段评价合理；未提供规范时明确限制，不引用不存在条款；不把开题计划当成实验成果 |
| A04 报告与证据 | R05、R06 | 报告符合约定结构；问题引用可定位；错误引文不能作为已验证问题发布；疑点保留待核实状态 |
| A05 真实模型与失败 | R04、R07 | 指定内部模型能够输出合法结构；请求超时、非法输出、超限时给出明确错误，不调用云模型 |
| A06 取消与持久化 | R10、R11、N03 | 取消后迟到结果不覆盖状态；刷新仍可查报告；重启将遗留任务标记 interrupted，不伪造恢复成功 |
| A07 联网边界 | R09、N01 | 模式 A 无任务驱动出网；模式 B 未批准／不匹配查询被拦截，批准记录与实际请求对应 |
| A08 查证深度 | R09、R12 | 区分书目元数据、摘要和全文；查无结果不等于文献虚构；外部证据可追溯到具体问题 |
| A09 语种与长文 | R02、R06、R12 | 满足语言默认及用户覆盖规则；超限不静默截断；分章后检查跨章一致性并列出未覆盖内容 |
| A10 专家与部署验收 | R04、R05、N01、N04、N05 | 专家核查实质意见；记录误报漏报及限制；确认资源、访问与出网策略符合批准范围 |

A01、A04、A06 的部分流程与相关失败边界已有自动化覆盖；其余尤其是 OCR、真实模型效果、网络级隔离和 A100 性能需要后续验证。模拟模式只识别 TODO 等标记，不能用于 A10 的学术质量验收。

建议由上游提供已授权的代表性样本及专家标注，覆盖四种材料、不同语言、文本与扫描件、已知问题和正常对照。样本数量、问题判定规则、允许误报漏报及耗时阈值在 D06 确认后固定；不将任意数字写成已承诺指标。

| D04 | 规范来源及适用范围 | 提供教育部、国科大、信工所及培养规定的具体文件、版本和适用对象，并指定维护人 | 只能做一般学术质量审查，不能完成具体制度合规核验 |
| D05 | Agent 自主工具调用范围 | 先固定工作流；如首期要求自主调用工具，另定工具清单、权限、预算与失败处理 | 当前 LangGraph 四节点不等同于模型自主工具调用循环 |
| D06 | 样本与验收口径 | 确认样本、专家、问题分级、误报漏报容忍度、篇幅及耗时目标 | 无法对实际学术审查质量和性能签收 |
| D07 | 访问与数据生命周期 | 确认单用户或多用户、数据保留期限、删除、备份、恢复及日志访问责任 | 本机 demo 不能直接作为共享正式服务 |
| D08 | 实施分工与交付窗口 | 明确应用开发、模型部署、网络安全、规范维护、专家验收负责人；资源落实后排期 | 无法形成可执行交付时间表 |

建议反馈格式：`事项编号｜同意或调整意见｜责任人｜目标时间`。本次确认应形成批准的首期范围、联网模式、接口基线、数据边界及验收责任；功能变更同步更新本文和方案版本。
